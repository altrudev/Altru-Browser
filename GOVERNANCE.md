# Project Governance

Altru Browser is currently maintained by Altru.dev.

## Decision model

Technical decisions are evaluated against:

1. standards conformance;
2. security and privacy;
3. architectural ownership boundaries;
4. portability;
5. measurable resource cost;
6. maintainability;
7. reproducible evidence.

No contributor, dependency, benchmark or external engine becomes semantic authority by reputation alone.

## Maintainer responsibilities

Maintainers are responsible for:

- reviewing contributions;
- protecting security and privacy boundaries;
- keeping capability claims proportional to evidence;
- managing releases;
- documenting breaking architectural decisions;
- preserving licensing and attribution.

## Community participation

Contributors can influence direction through issues, proposals, tests, implementation work and evidence. Significant architectural changes should begin with an issue or design proposal before a large implementation PR.

## Private development assurance

Altru.dev may use private internal tooling to design, test or audit changes. Public contributions do not depend on access to those tools. The public repository must remain independently buildable and reviewable.

## Changes to governance

Material governance changes should be made through a pull request with a clear rationale.
